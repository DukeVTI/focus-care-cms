 Focus Developer Instructions: FocusCMS Calendar &amp; Scheduling Module 1. User Experience &amp; Core Calendar Interface (Frontend) The calendar interface must prioritize simplicity and mobile responsiveness. Requirement Specification Interface Design Must be clean, intuitive, and follow established UI/UX patterns (e.g., Google Calendar, Outlook). The design must be mobile-first and fully responsive to ensure seamless usability on all devices. Dual Calendar View The module must offer two distinct viewing modes, easily switchable by the user: 1. Individual Calendar: Shows only the user's scheduled items (dates, tasks, meetings). 2. Group Calendar: Shows all scheduled meetings and group activities for the user's assigned team or project scope. 2. Event and Task Diarization Logic The system must support two primary event types: Meetings and Tasks , each with specific tracking requirements. 2.1 Meeting Diarization Scheduling: Standard event creation fields (Title, Date/Time, Participants). Data Unification: To facilitate later data mining, all critical meeting attributes must utilize standardized, predefined drop-down options instead of free-text entry where possible. Required Dropdown Fields: Meeting Type (e.g., Case Review, Staff Briefing, Training), Location (e.g., Office A, Remote, Client Site), Status (e.g., Scheduled, Cancelled). 2.2 Task Diarization Task Fields: Title, Description, Assigned User(s), Deadline Date. Completion Tracking: Tasks must include a mandatory status field with the following specific options: Completed: Marks the task as finished. Pending: The default active status. Postponed: If selected, the system must prompt the user to immediately enter a new required deadline date . 3. System Integration &amp; Communications 3.1 Windows Integration (Meetings) The platform must offer seamless integration with Windows (Outlook/Windows Calendar) for any scheduled meeting. This must be achieved by providing an option upon saving a meeting to generate and attach an iCalendar (. ics ) file to the meeting confirmation. This file allows participants to easily add the event to their native Windows/Outlook calendar application. 3.2 Email Notification System The system must incorporate a robust, automated email notification service for both meetings and tasks. Meeting Reminders: Participants must receive email notifications: Immediately upon scheduling. A configurable reminder interval before the event (defaulting to 24 hours prior). Task Notifications: Users assigned to a task must receive email notifications: Upon initial assignment. As a reminder if the task status is Pending and the deadline is approaching (e.g., 48 hours prior). 4. Reporting and Data Tracking The module must capture specific metadata to enable effective analytics. Activity Type Tracking: A mandatory, unified drop-down field must be included in the meeting/activity creation form to categorize the nature of the event (e.g., 1:1 Supervision, Group Therapy Session, Administrative Work, Training, etc.). This standardized classification is crucial for reporting. Graph Type Reporting: The collected data (specifically the Activity Type and Status data) must be structured to support future reporting capabilities, allowing for data mining and the generation of visual reports (e.g., bar charts, pie charts, or line graphs) that track: Volume of meetings/activities by Activity Type . Task completion rates over time ( Completed vs. Postponed ). Time allocation across different Activity Types.
